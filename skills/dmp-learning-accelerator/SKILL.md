# Deep Mastery Protocol (DMP) — Learning Accelerator

> **Core Goal**: Engineer the learning process itself, make tacit knowledge explicit, and achieve rapid cognitive iteration.

---

## 🧠 Four Cognitive Pillars

| Pillar | Principle | How It Is Enforced |
|--------|-----------|-------------------|
| **Bloom's Taxonomy** | Go beyond application — target analysis, evaluation, and creation | Write KnowledgeBase notes at the analysis level |
| **Pareto 80/20** | Focus on the 20% of high-value core knowledge | Mark critical topics with `[CORE]` in Roadmap |
| **Spaced Repetition** | Combat the forgetting curve | Embed `[Review: DayXX]` markers in Roadmap |
| **Ultralearning** | Targeted drill sessions at bottlenecks | Trigger `drill(topic)` commits |

## 🚀 Step 0: Bootstrap (First-time setup only)

When the user says "start a new learning project", **you must** execute:

```bash
# 1. Create directory structure
mkdir -p Reference Engineering Protocol KnowledgeBase Gallery src/common Verification tools

# 2. Ask the user: learning domain, target duration, primary tech stack
# 3. Generate the following core files (see individual template sections):
#    - README.md
#    - Roadmap.md  (lesson outline with [CORE] markers)
#    - SyncState.md  (initial state)
#    - Protocol/DEEP_MASTERY_PROTOCOL.md  (this protocol)
#    - Engineering/Standards.md  (domain-specific standards)
#    - tools/scaffold_lab.sh  (automated scaffold script)
# 4. git init && git add . && git commit -m "chore: bootstrap DMP learning project"
```

### Three Required Bootstrap Questions

1. **Learning domain** — e.g. "OpenGL graphics", "Rust systems programming", "distributed systems"
2. **Target duration** — e.g. "30 days", "60 days", "chapter-by-chapter with no deadline"
3. **Per-lesson deliverable** — e.g. "runnable demo", "code + notes", "notes only"

## ✈️ Gated Execution Checklist (Four Gates Per Lesson)

> **Core Rule**: You may not enter the next gate until the current Gate Output is complete.

### 🔒 Gate 1 — Launch & Environment Lock

- [ ] Read `SyncState.md` (current progress) and `Roadmap.md` (today's topic)
- [ ] Run `./tools/scaffold_lab.sh <day> <topic>` to generate the scaffold
- [ ] Declare `[PLAN]: I will implement X, expected output Y, core knowledge Z`

**🚩 Gate Output 1**: Scaffold created, PLAN declared

### 🔨 Gate 2 — Build & Verification

- [ ] Write code (**Zero-Placeholder Policy** — no stubs or TODOs)
- [ ] Expose all key parameters through UI (ImGui / CLI flags / config file)
- [ ] Build reaches **0 Errors, 0 Warnings** (`-Werror` or equivalent)
- [ ] Launch the program; visually or programmatically verify no abnormal output
- [ ] Save screenshot/recording to `Gallery/Day_XX_<Topic>.png`
- [ ] `git commit -m "feat(lab/XX): core logic verified"`

**🚩 Gate Output 2**: Screenshot path + commit SHA

### 🧠 Gate 3 — Distillation & Consolidation

- [ ] Create `KnowledgeBase/Day_XX_<Topic>.md` (see note template)
- [ ] Incrementally update `Reference/Glossary.md` (new terms)
- [ ] Incrementally update `Reference/QuickRef.md` (new snippets)
- [ ] Incrementally update `Reference/MentalModels.md` (new intuitions)
- [ ] `git commit -m "docs(kb/XX): distillation complete"`

**🚩 Gate Output 3**: KB summary + list of new reference entries

### ⚖️ Gate 4 — Audit & Handover

- [ ] Submit MIR report (see template)
- [ ] Clean up temporary files
- [ ] Update `SyncState.md` (Handover Note must be crystal-clear)
- [ ] `git commit -m "sync: Day XX complete"`

**🚩 Gate Output 4**: MIR report output

## 📝 KnowledgeBase Note Template

Every Feynman note must include the following sections (targeting Bloom's analysis level):

```markdown
# Day XX: <Topic>

## Core Question
> In one sentence: what problem does this lesson solve?

## Derivation / Theory
<!-- Mathematical formulas (LaTeX) / algorithmic logic / data-flow diagrams -->

## Core Code Walkthrough
<!-- GLSL / Rust / Python core snippets with line-by-line comments -->

## Expected Output Description
<!-- What should you see/get after running? Describe using sensory language. -->

## Pitfalls & Retrospective
<!-- Problem encountered + root cause + fix -->

## Connections to Prior Knowledge
<!-- Related Days: Day 03 (VAO), Day 08 (Phong) -->

## Self-Test Q&A
<!-- Q: Why use GL_LEQUAL instead of GL_LESS?  A: ... -->

## Asset Sources
<!-- Record origins of textures/models to avoid copyright issues -->
```

## 📮 Git Commit Convention

| Type | When to Use | Example |
|------|-------------|---------|
| `feat(lab/XX)` | Code runs and is verified | `feat(lab/17): logic verified` |
| `docs(kb/XX)` | Notes and documentation complete | `docs(kb/17): complete deep dive` |
| `docs(assets)` | Reference assets synced | `docs(assets): update glossary day 17` |
| `docs(gallery)` | Screenshot / GIF added | `docs(gallery): add Day 17 snapshot` |
| `drill(topic)` | Targeted practice code | `drill(matrix): practice lookAt impl` |
| `refactor(core)` | Utility extracted to common | `refactor(core): extract Camera helper` |
| `docs(retro)` | Bug retrospective recorded | `docs(retro): debug shadow map matrix order` |
| `sync` | End-of-lesson global sync | `sync: Day 17 complete` |

## 🔧 scaffold_lab.sh Template

Generic scaffold script template — replace `# TECH-SPECIFIC` sections for your tech stack:

```bash
#!/usr/bin/env bash
# DMP Lab Scaffolder — Generic Template
# Usage: ./tools/scaffold_lab.sh <day_number> <topic_name>
set -e

DAY="$1"
TOPIC="$2"
DIR="src/${DAY}_${TOPIC}"

[[ -z "$DAY" || -z "$TOPIC" ]] && echo "Usage: $0 <day> <topic>" && exit 1
[[ -d "$DIR" ]] && echo "Directory $DIR already exists!" && exit 1

mkdir -p "$DIR"

# TECH-SPECIFIC: generate main entry file (replace extension and boilerplate per domain)
cat > "$DIR/main.<ext>" << 'EOF'
// Day ${DAY}: ${TOPIC}
// [PLAN]: TODO — fill in this lesson's implementation goal
EOF

# Generate KnowledgeBase template
cat > "KnowledgeBase/Day_${DAY}_${TOPIC}.md" << EOF
# Day ${DAY}: ${TOPIC}

## Core Question
> TODO

## Derivation / Theory

## Core Code Walkthrough

## Expected Output Description

## Pitfalls & Retrospective

## Connections to Prior Knowledge

## Self-Test Q&A

## Asset Sources
EOF

echo "✅ Scaffolded: $DIR"
echo "📝 KB template: KnowledgeBase/Day_${DAY}_${TOPIC}.md"
```

## ⚠️ Mandatory Constraints (Safety Protocol)

1. **Zero-Placeholder Policy**: Never commit code or documentation containing `(...)`, `TODO`, `...`, or other stub markers.
2. **Zero Warning Policy**: All compiler warnings are treated as errors and must be fixed immediately.
3. **Progression Integrity**: Advanced content must never overwrite the baseline version — always create a new independent directory.
4. **Handover Awareness**: `SyncState.md` must be updated at the end of every session to leave clear handover information for the next agent.
5. **Read-Back Verification**: After modifying any core document, actively read it back to verify completeness.
6. **Math Rigor**: Formulas must be recorded in LaTeX — natural-language substitutions are not permitted.

## 🎯 Definition of Success

A DMP learning project is considered successful when all five dimensions are met:

| Dimension | Criterion |
|-----------|-----------|
| **Code runs** | `src/` projects verified; `Verification/` tests pass |
| **Principles explained** | `KnowledgeBase/` reaches Bloom's analysis/evaluation level; Self-Tests pass |
| **Assets retained** | `Reference/` system is complete; any mental model can be retrieved in under 5 minutes |
| **Memory recalled** | Spaced repetition track is active; prior lessons reviewed on schedule |
| **Tools reusable** | `src/common/` forms a portable utility library |
